COO Track · Session 4 — Critical Path & Collection Milestones

Track COO · Rey Direction module · 30–45 min Sources: canon §2/§4 · EL_FLOW · template maestro
The critical path is also the money path: each finished, documented trade becomes a collection (REQUEST BANK PAYMENT → RECEIVE BANK PAYMENT). A red tag does not just delay a trade — it delays the draw behind it. Quality IS money.

1 · Objective

This section exists so you know what "done" looks like. Protect the critical path as the company's collection engine: know each project's next milestone, the chain that blocks it, and what to verify on site so it never slips silently.

2 · Content

The physical critical path (canon §2)

  • The staggered template: MEP in-ground → foundation (formboard · survey · report · pour · ~10 days curing) → framing → sheathing/decking → exterior doors&windows → MEP rough-ins → framing inspection → interior chain (zip tape → insulation → drywall → primer → floors/tiles → carpentry → cabinets → countertops → MEP trims → final paint) → walk → punch → final inspection.
  • "Una cosa te va bloqueando la otra" — it stretches, never shrinks. Blue = critical; the interior chain is the longest.
  • The official template RULES: 34 trade groups · 411 tasks (TEMPLATE_MAESTRO_JOBTREAD_2026-08-06.csv).

The golden rule (EL_FLOW) — what the COO enforces

  • An EXECUTE only holds a date if its chain is 100% closed: SOW → signed WO → sub confirmed → material with ETA → Before inspection.
  • Practical form at the 2:30 meeting: EXECUTE dated this week → its previous tasks must be at 100%. If not, the EXECUTE moves — never left "just in case".

Collections (EL_FLOW Fase E)

  • Trade closed + documented (After checklist · city inspection passed if required) → REQUEST BANK PAYMENT → RECEIVE BANK PAYMENT. The CEO manages the draw; the COO guarantees the work side is truly closed so the draw is requestable.
  • Milestone movement (Next Week gerencia report): per project — which collection is next, HOW MUCH, WHEN, chip "SE COBRA ESTA SEMANA", and "how this week brings it closer" (built only from tasks the schedule itself chains to the collection — never invented causality).

3 · The real case

Case #3 — Martha's red tags (24-jul): inspections rejected for wrong sequence requested and plans not physically present on site — the exact failure that had been predicted. The COO's site verification (sequence correct + approved plans on site, BEFORE the PM calls the city) is what prevents it.
The real chain (Martha): framing inspection → siding → siding+drywall collection, $44k. Three days late on siding = $44k arriving late. That is how the COO reads a delay: in dollars against the milestone.
Case #8 — crossed material: a sub using Martha's material on something else — detected by chat, not by system. Material that enters a job belongs to THAT job; the COO is the pair of eyes on site.

4 · The exercise

On one real project: map its next collection milestone — (1) which schedule tasks chain to it, (2) which of those are at risk THIS week, (3) what you verify on site tomorrow so the inspection passes FIRST time. Then write the 3-line escalation for one chain task whose predecessor is not closed (what · who unblocks · by when).

5 · What gets evaluated

  • For any active project: names the next milestone (amount + blocking chain) without opening the budget.
  • Zero EXECUTEs allowed through the 2:30 meeting with an open chain, in the projects he visited.
  • Inspection prep verified on site (sequence + plans present) before the city is called.
